# 화면 명세 (Screens) — 와이어프레임 그대로

> 진실원천: `docs/reference/wireframe.html`. 아래는 그 내용을 화면별로 정리한 것.
> **정보 구조·필드·컬럼·문구·플로우는 그대로 재현**하고, 비주얼만 프로젝트 디자인 토큰으로 입힌다.
> 브라우저에서 `wireframe.html`을 열어 실제 배치도 함께 확인할 것.

공통(앱 화면): 상단 헤더 = `AI 순찰 시스템` 브랜드 + `관리자 ▾ | 로그아웃`. 좌측 사이드바 = **Dashboard · 순찰관리 · 이벤트관리 · 로봇관리 · 통계 · 알림**. 본문 상단에 브레드크럼(`Dashboard > …`).

## 로그인 `/login` (1a)
- 제목: **AI 순찰 로봇 관리자 로그인**
- 필드: 아이디(placeholder "아이디 입력"), 비밀번호("비밀번호 입력")
- 버튼: **로그인** → 성공 시 `/app`

## 회원가입 · 일반 회원 `/signup` (1t)
기존 단지 소속 회원. (와이어프레임엔 ERD 근거가 주석으로 있지만 화면엔 노출 안 함.)
- 필드(순서 그대로):
  - **아이디** — placeholder, 규칙 "4~20자 영문/숫자", [중복확인] 버튼. 인라인 에러: "✕ 이미 사용중인 아이디입니다"
  - **비밀번호** — 규칙 "8자 이상, 영문+숫자+특수문자 조합", **강도 표시**(예: ●●○ 보통)
  - **비밀번호 확인** — 인라인 에러: "✕ 비밀번호가 일치하지 않습니다"
  - **이름**
  - **닉네임** — [중복확인]
  - **전화번호** — placeholder "010-1234-5678", 입력 중 **자동 하이픈 포맷**
  - **아파트단지** — 필수. "🔍 아파트단지를 검색해 선택하세요" + [검색] → 검색 모달. 미선택 시 제출 Toast "아파트단지를 선택해주세요"
  - **[ ] 이용약관 및 개인정보처리방침에 동의합니다**
- 버튼: **가입 완료**
- 주의(주석): 회원상태·가입일시·수정일시는 서버 자동 생성 → 화면 미노출.
- **아파트단지 검색 모달**: 제목 "아파트단지 검색", 검색 인풋(아파트 이름/주소). 결과 테이블(아파트 이름 / 도로명주소 / [선택]). 예: `가온아파트 · 서울시 OO구 OO로 12`. 하단: "찾으시는 단지가 없으신가요? **신규 아파트단지 등록(최초 가입자) →**" (→ `/signup/onboarding`). 검색 결과 없으면 온보딩으로 유도.

## 회원가입 · 최초 가입자 온보딩 `/signup/onboarding`
단지의 첫 관리자. 상단 스텝 인디케이터 공통: **[① 계정·단지] [② 로봇 등록] [③ 맵 등록]**

### Step 1/3 — 계정·단지 (1u)
- 제목 **최초 가입자 등록** / 설명 "이 단지의 첫 관리자입니다. 계정과 단지 정보를 함께 등록합니다"
- 계정: 아이디 / 비밀번호 / 이름 / 닉네임 / 전화번호
- **신규 아파트단지 정보**: 우편번호 + [우편번호 찾기] / 아파트 이름 / 도로명주소
- 버튼: **다음: 로봇 등록 →**

### Step 2/3 — 로봇 등록 (1v)
- 제목 **첫 순찰 로봇 등록** / 설명 "로봇 본체에 표기된 일련번호로 이 단지의 첫 로봇을 등록합니다. 등록된 로봇이 다음 단계에서 단지 맵을 직접 파악합니다"
- 필드: **로봇 일련번호 입력** (예: `SN-2026-0001` "로봇 하단 라벨 표기") / **로봇명**
- 안내: "담당 구역은 맵 파악이 끝난 뒤 자동으로 지정됩니다"
- 버튼: **← 이전** / **다음: 맵 파악하기 →**

### Step 3/3 — 맵 파악 (로봇 자동 스캔) (1w)
- 제목 **로봇이 단지 맵을 파악합니다** / 설명 "[맵 파악하기]를 누르면 로봇이 단지를 순찰하며 스스로 맵을 그립니다. 지도를 직접 올릴 필요가 없어요"
- 액션 **[ 맵 파악하기 ]** → 진행률(예 68%) + `[ SCANNING… ]` + "파악된 영역 12,400㎡ / 18,200㎡" → 완료 `[ 파악 완료! ]` "맵 파악이 끝나면 구역 지정 단계로 넘어갑니다"
- 버튼: **← 이전** / **다음: 구역 지정 →**

### Step 3/3 — 구역 지정 (IoT 수신 맵 위 드래그 · 인터랙티브) (1y)
- 제목 **구역을 드래그해서 등록해주세요** / 설명 "로봇이 보낸 맵 데이터를 화면에 그려드려요. 구역 유형을 선택한 뒤 맵 위를 드래그하면 해당 구역이 등록됩니다 (✕로 삭제)"
- 좌: 구역 유형 선택 팔레트(주차장/분리수거장/위험구역 등). 우: `[ IoT MAP · 수신됨 ]` 그리드 맵(열 A~N, 행 1~7). 맵 위 드래그로 사각 구역 생성, 각 구역 라벨 + ✕ 삭제.
- 완료: `[ 맵 등록 완료! ]` "드래그한 구역 N곳이 저장되었습니다"
- 버튼: **← 이전** / **가입 완료 →**

### 완료 (1x)
- **회원가입이 완료되었습니다** / "가온아파트 단지 등록 · 로봇 1대 등록 · 맵 파악 완료" / `[ 구역 5곳 등록 완료 ]`
- 버튼: **대시보드로 이동** (→ `/app`)

## 대시보드 `/app` (1c)
관제 메인. 실시간 지도(확대 보기) + 요약. (와이어프레임 1c 기준 — 지도/최근 이벤트/로봇 상태 요약 위주로 구성.)
- 로봇 상태 요약: `R-01 78% [순찰중]` · "금일 순찰 2회 완료 · 1회 진행중"
- 긴급 · 미처리 바로가기: `[ 긴급 1 ] [ 확인중 1 ] [ 미처리 1 ]`
- 최근 이벤트 테이블: 시간 · 유형 · 위치 · 상태

### 긴급 알림 모달 (1c+) — 긴급상황 발생 시 대시보드 위에 표시
- 헤더: `[ 긴급 알림 ]` + 현재 시각(초 단위)
- 본문: `⚠ 응급상황 감지 — 쓰러짐 의심` / "위치: 지하주차장 B2 · 탐지로봇 R-01 (현장 대기중)" / "신뢰도 92% · 경과 0분 12초"(실시간)
- 버튼: **즉시 확인 →** (→ 긴급 이벤트 상세 1o) / **5분 후 다시 알림**

### 지도 확대 보기 (1h) — 지도 전용 풀스크린 `/app/map`
- 상단 바: `[ LIVE MAP · 체크포인트 + 이동 경로 ]` / `[ 실시간 연결됨 ]` / **✕ 닫고 대시보드로**
- 맵: 체크포인트(🚩 출발지 · 🗑 분리수거장 · 🅿 주차장 A · 🅿 주차장 B) + 점선 이동 경로 + `🤖 R-01 · 순찰중` + 빨간 `[ 긴급 · 지하주차장 B2 ] ← 클릭`
- 빨간 포인트 클릭 → **긴급 알림 패널**: `[ 긴급 알림 ]` + ✕ / 응급상황 (쓰러짐 의심) / 위치·탐지시각·경과(실시간)·탐지로봇 (현장 대기중)·신뢰도 / 현장 스냅샷 (R-01 전송) / **긴급 이벤트 상세 보기 →** (→ 1o) / **보안 출동 요청**

### 긴급 이벤트 상세 (1o) — 1c+ 모달의 [즉시 확인 →]으로 진입 (`/app/events/:id`의 긴급 변형)
- 제목: `⚠ 긴급 이벤트 상세 — E-3313` + `[ 긴급 · 즉시 확인 필요 ]`
- **긴급 판단 사유** 배너: "AI가 응급상황(쓰러짐 의심 인물)을 92% 신뢰도로 탐지 — 최근 5분 내 동일 위치 재탐지로 자동 \"긴급\" 승격됨"
- 증거 이미지 라벨: `[ R-01 현장 이미지 · 14:32 수신 ]`
- 메타: 유형 응급상황(쓰러짐 의심) · 탐지시각 14:32 · 위치 지하주차장 B2 · 탐지로봇 R-01 (현장 대기중) · 신뢰도 92% · 경과시간(실시간)
- 액션: **보안 출동 요청** / **입주민 긴급알림 발송**

## 공통 상태 태그(뱃지) 매핑 → 토큰
- **완료 / 이상무 / 정상 / 순찰중(온라인)** → `success`
- **진행중 / 확인중 / 수신됨** → `info`
- **미처리 / 점검필요 / 주의** → `warning`
- **긴급 / 응급상황 / 침입** → `danger`
`StatusBadge` 컴포넌트 하나로 처리(라벨 → tone 매핑 테이블). `docs/components.md` 참고.
